# 社区运行与正式版迁移（2026-09-08）

## 当前可以做什么

公网版本使用 D1 持久数据库和 R2 图片存储。用户、地点、评论、图片元信息、举报和审核记录分别存表，图片文件存 R2；前端代码与这些数据分离。更新网站不会清空数据。

当前登录依赖 ChatGPT 平台身份，数据库保存站点身份 ID、展示名称和创建时间，不保存用户密码。它并不是面向所有国内用户的独立手机号注册系统。不能把模拟身份并发测试当作真实用户完成平台注册的证明。

游客可投稿；登录后可留言、回复、提交现场状态和带图评价。投稿及评论默认待审；作者可以看自己的待审内容，公众只能看已批准内容。未批准图片同样受访问控制。管理员在管理页审核，版本检查防止覆盖别人的审核，审核事件保留记录。审核后详情页可见期间每 15 秒同步评论，切回页面时也同步；这不是即时推送，审核耗时另算。

每人每地点只取最近一次已审核到访评分，重复到访不会重复增加评分人数；不足 5 人不进入榜单。样本少、刷分或同一人多账户仍可能造成偏差，不能因为网站没有商业利益就宣称评分绝对真实。

## 已完成的验证

- 编译后 Worker 在真实 workerd + 隔离 D1/R2 中运行：注册档案并发创建、防重复投稿、带图评论（临时文件名无扩展名）、游客拒绝评论、待审图片隔离、人工批准、撤回隐藏、回复依赖父评论、评分人数去重、审核版本冲突，以及重启后评论和图片仍在。
- 100 个模拟已验证身份、20 个并发请求工作流、504 次请求通过，无重复用户/评论。优化后本机 p50 214 ms、p95 678 ms；这是本机结果，不是生产 SLA，也没有模拟真实 OAuth 注册。
- 浏览器填写四维评分并投稿成功；匿名窗口批准前 0 条、批准后自动出现 1 条；作者未发送草稿保留。
- 所有测试数据位于临时隔离数据库，不向生产批量灌入测试用户、评论或照片。

尚未证明：大陆三网无 VPN 可用、100 个真人登录、长期线上并发容量、第三方身份服务容量、生产备份恢复。正式推广前必须完成这些验收；若入口域名或身份服务不可达，仅优化页面资源不能解决。

## 正式版迁移顺序

1. 选择部署地区、正式域名、国内可用的身份验证服务及地图服务，再确定数据库目标。没有必要仅因为有用户表就拆成两套数据库；权限和最小化采集更关键。
2. 为 D1 所有表建立完整导出与恢复流程，另导出 R2 图片及对象键清单；源数据量、关联关系、状态、来源授权信息、审核历史、图片校验值一起记录。当前还没有完成生产全量导出/恢复演练，不承诺一键迁移。
3. 在隔离预发布环境恢复数据库和图片，保留地点/评论/用户内部 ID 与关联关系；如果换 PostgreSQL/MySQL，转换 SQL 类型与查询，先验证再切换。
4. 重点处理身份关联：平台用户 ID 可能受站点范围限制，不能假定换平台后仍相同。通过旧身份验证把旧用户绑定到新登录方式；不能凭展示名认领历史评论。
5. 切换前短暂停写，执行最终增量迁移，核对数量、图片、权限、审核队列和评分结果；切换域名后保留旧环境与备份用于回滚。切换后的新写入也需明确回收方案，不能只切回旧库而丢数据。
6. 国内正式运营前核实备案、内容治理、个人信息处理与地图相关要求；选定服务商后再落实，不以当前公开预览地址代替合规验收。

## AI 审核建议（尚未启用）

先采用“AI 辅助 + 人工最终批准”：文本/图片安全检测，再由 GPT-5.6 Luna 按社区规则给出建议及疑点，管理员决定是否公开。AI 不能验证真实到访、当前卫生、精确入口或图片授权；隐私、疑似盗图、地点争议交给人工。失败、超时、额度不足时保留待审，不能默认放行。

ChatGPT/Codex 订阅和 API 独立计费；公开网站不能直接消耗个人 ChatGPT 订阅来持续调用模型。GPT-5.6 Luna 有 API，可用独立服务端密钥接入。密钥不得放前端。若后续启用，应先批准模型调用预算、数据发送范围、审核流程及新增审核记录字段，再实施。
