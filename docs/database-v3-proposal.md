## 目的与范围

现有版本在正式模式关闭验证、登录和投稿，不能通过简单打开开关上线。管理员也不能修正待规范地区或给出可查询的拒绝原因。补齐以下数据能力后，才能实现对应的身份和审核流程。

1. 正式身份关联：账号与身份提供方的不透明主体标识关联，支持游客验证后的投稿关联，不向公开接口输出身份信息。具体提供方待运营资源确定后选定。
2. 验证用途和消费状态：区分注册、游客投稿等用途，记录过期、尝试次数和已消费状态；真实验证码不明文持久化。测试验证与正式验证隔离。
3. 地点版本与修订：管理员可纠正地区、入口、路线及其他已有资料字段，保存修订前后内容、操作者及时间；使用版本检查防止覆盖其他管理员的更新。
4. 审核原因：通过、拒绝、下架、纠错处理记录具体理由；回执只显示适合投稿者查看的原因，内部备注不公开。

## 迁移约束

- 只在本地及隔离环境开始，生产数据库不在授权范围内。
- 迁移前一致性备份；有版本号、重复执行保护及明确失败恢复过程。
- 保留已有用户、来源、照片、评价、回执及审核状态；不将演示身份转换为已验证的正式身份。
- 不猜测旧记录的区县、真实身份、审核原因或创建时间。
- 密钥不入库、不写入代码或示例文件；日志不输出验证码与身份凭据。
- 先用隔离测试验证升级、已有数据保留、并发修订、越权拒绝和回执信息边界，再考虑迁移本地体验库。
