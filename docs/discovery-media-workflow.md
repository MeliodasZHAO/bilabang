# 实拍短片如何补片

`node ops/discovery-media.mjs scan` 扫描已登记的公开话题和搜索页，取出原帖地址，合并同 ID 的链接，标出广告和用品类噪声，并重新检查本批已核片内容的播放器。报告在 `output/discovery-media/review.json`。每次结果取决于平台当时公开暴露的信息。

小红书在搜索页未返回可公开获取的原帖地址时，报告会保留情况及定向搜索入口。可将公开搜索或 App 分享得到的**原帖长链接**放在文本文件中，用 `node ops/discovery-media.mjs scan output/links.txt` 一起去重。不调用登录接口、不会尝试突破登录限制。

将找到的重点线索登记到 `ops/discovery-media-queue.json`。优先补上没有覆盖的城市，并分别积累景区、酒店和山野。每条拟展示的短片至少要能回答以下问题。

- **这是哪处。** 原帖写明地点，画面能对应，并有景区、酒店、设计方或直接采访其负责人的报道支持。景区层级能确认而单体入口不明时，在前台明确写出来。相邻驿站、同名酒店或不同楼层不能混用。
- **有什么可看。** 实拍中确实出现厕所本体、盥洗空间或明确有关系的建筑与景观。备注可复看的时间、画面，以及它区别于普通厕所之处。游客提到如厕、迷人的酒店外景、拼图或高点赞都不能替代镜头。
- **可公开展示什么。** 保留原平台、作者、日期及出处。核查隐私，搁置拍到实际如厕、未授权转载或不能确认公众访问的材料。使用抖音官方播放器或者链接到持有视频的原文，不把作者视频或截帧复制到本站。住客空间和历史影像注明边界。

完成核片后标为 `approved`，填写 `film` 与 `review`。执行 `node ops/discovery-media.mjs publish` 才写入公开片单；已有条目按 ID 保留。本批若有任一拟发布条目证据不全、冲突或播放器失效，整批不写，原因记在 `output/discovery-media/release.json`。最后构建，在手机和桌面尺寸下抽查片单、筛选和原片，再按静态前端流程发布。

老片可用 `node ops/check-discovery-media.mjs` 复查。失效先回到待核，同一地点补对应原片。运行命令只写报告或静态片单，不写用户数据或生产数据库。
